# Missouri Public-Data Source Research

This project uses a source-first pattern: catalog official public sources, estimate access and size, then add deterministic lookup or retrieval before asking the local model to explain anything.

## Recommended Product Direction

1. Contract explainer: best immediate feature. It combines contract metadata, public document links, optional PDF text extraction, and MAP vendor-payment context.
2. Auditor/DOR/MEC explainers: high transparency value because users can ask what an audit, public revenue report, or campaign-finance filing means.
3. DESE school directory, APR rankings, finance transfers, special-education incidence, and public aggregate school data: selected data.mo.gov education counts, DESE School Data resource metadata, the selected DESE School Directory PDF, selected 2025 APR ranking PDFs, selected 2025-2026 DESE finance transfer PDFs, and the selected statewide special-education incidence PDF are now indexed; full DESE numeric accountability, staff, assessment, budget, audit, district profile, and broader finance exports still need dedicated parsers.
4. DHSS aggregate county profiles and long-term-care inspection sources: high value; the selected communicable-disease report parser, selected BRFSS statewide aggregate parser, selected statewide vital-statistics parser, selected MOPHIMS statewide/profile plus selected county leading-causes-of-death and inpatient parser, selected WIC aggregate parser, selected LTC directory/census parser, and DHSS LTC inspection resource/filter metadata parser are now done, but all-county profile values, broader MICA/PAS query values, county-level births/deaths, county-level BRFSS, facility findings, complaints, and survey findings still need source-specific parsers.
5. data.mo.gov catalog-driven additions: use the local catalog metadata search to select stable datasets instead of guessing URLs.

## Local-Only Constraints

- Raw downloads stay under `data/raw_public/` and are ignored by Git.
- Contract PDFs are capped by `--limit` and `--max-mb`.
- Health and education ingestion should prefer aggregate public outputs.
- The chatbot should refuse private identifiers, full table dumps, and unsupported claims.
