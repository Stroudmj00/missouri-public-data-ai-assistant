## Interpretation

This is a small portfolio case-study evaluation. It is useful for showing reproducibility, model behavior, and iteration discipline, but it is not a broad benchmark.

## Runtime Routing Evaluation

The runtime tests now report behavior by category instead of only a single pass count. Each API answer carries a common evidence/deep-answer shape:

- `retrieval_path`: deterministic lookup, retrieved QA, ordinary chat, or guardrail
- `source_family`: the public-data family selected by the router
- `evidence_type`: exact public-record lookup, exact aggregate lookup, source discovery, document text lookup, ordinary chat, or guardrail
- `routing_confidence`: score used for reviewer diagnostics
- `guardrail_reason`: populated for private-identifier, unsupported-scope, or low-confidence retrieval refusals
- `route_candidates`: the top ranked source-family candidates considered for the question
- `evidence_tool_calls`: controlled local evidence tools used before synthesis
- `evidence_hits`, `evidence_bundle_id`, and `raw_evidence_summary`: the cited local evidence package sent to Deep Answer or returned as fallback
- `available_evidence_tools`: the tool names exposed to the deep-answer layer
- `deep_answer_status`: `synthesized`, `unavailable_fallback`, `provider_error_fallback`, `guardrail_preserved`, or `not_applicable`
- `deep_answer_provider` and `deep_answer_model`: provider identity for synthesis/fallback audits
- `confidence`, `limitations`, and `local_verification`: reviewer-facing evidence and safety checks

The category summaries are generated by:

```powershell
.\.venv\Scripts\python scripts\test_assistant_behavior.py
.\.venv\Scripts\python scripts\test_source_usefulness.py
```

The behavior script keeps its historical filename, but the report is interpreted as the assistant behavior suite.

Current categories:

- routing accuracy
- exact public-record lookup
- source discovery
- citation/source-link quality
- privacy/private-identifier guardrails
- unsupported or future-looking guardrails
- ordinary general chat
- retrieved QA fallback when fixed generated QA is the only supported route
- tool-based evidence retrieval
- multi-step comparison questions
- ranking or trend-style questions
- unsupported complex questions
- privacy-sensitive complex questions
- missing Vertex credentials fallback

This keeps the case study focused on source-grounded retrieval and controlled synthesis. Vertex AI Gemini is the default deep-answer provider when credentials are configured. Tests use fake and unavailable providers so the default suite still passes without cloud credentials.

## Deep Answer Provider Evaluation

The behavior suite includes fake-provider cases that prove the provider layer can synthesize over evidence without calling Vertex AI. It also includes a missing-provider case that proves the app returns local evidence output with `deep_answer_status: unavailable_fallback` instead of crashing.

The evaluated provider states are:

- `synthesized`: fake provider rewrites a cited evidence answer while preserving the underlying local result
- `guardrail_preserved`: privacy and unsupported complex requests do not go to synthesis
- `unavailable_fallback`: Vertex-style provider is unavailable, so the assistant returns local evidence output
